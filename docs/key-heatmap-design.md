# Тепловая карта и маршруты нажатий — спецификация

Статус: согласовано 2026-10-02. План реализации: [key-heatmap-plan.md](key-heatmap-plan.md).

## Цель

Видеть, какие клавиши и как часто нажимаются, чтобы найти неиспользуемые и
перегруженные клавиши, а также маршруты пальцев («после клавиши X чаще всего
жму Y») — как основу для оптимизации раскладки.

## Решения

### Где живёт

- Встроенный модуль Entropy (системы плагинов нет). Сначала форк, затем PR в
  `ergohaven/entropy`, поэтому сразу: i18n (en/ru), тесты, никаких допущений
  под конкретную клавиатуру.
- Подраздел «Тепловая карта» во вкладке `Advanced`, рядом с Typing Trainer.

### Сбор данных

- Источник — существующий опрос матрицы Vial (`VIA_SWITCH_MATRIX_STATE`,
  16 мс по USB / 80 мс по BT). Считаются фронты нажатия физических клавиш.
- Активный слой берётся из симулятора слоёв Layout Indicator
  (`src/ui/layout_indicator.rs`), который становится общим компонентом.
  Для K:03 v3/v4 пользователя (только `MO`, tri-layer 1+2→3) он точен.
- Переключатель «Собирать статистику» на странице, по умолчанию выключен.
  Когда включён — собирает, пока Entropy открыт или свёрнут в трей.
- Автопауза: открыт Matrix Tester; идёт Typing Trainer; клавиатура
  заблокирована в Vial (показываем «сбор на паузе — разблокируйте»).
- Хранятся только агрегаты (никакого лога и текста): по клавиатуре, по дням
  (локальная дата), без срока давности; на диске — файл на месяц.

### Что считается

- Единица — (слой, физическая позиция в матрице).
- Клавиши `MO(n)` считаются нажатием на слое, где их нажали.
- Комбо — как отдельные физические нажатия своих клавиш.
- Энкодеры не учитываются (не в матрице).
- Переходы:
  - только внутри одной половины сплита; половины определяются по самому
    широкому (≥ 1,5u) разрыву X-координат центров клавиш; если разрыва нет —
    клавиатура считается одной половиной (деление строк пополам отброшено:
    оно ломало бы несплитовые клавиатуры);
  - `Л1 → П1 → Л2` даёт переход `Л1 → Л2` (следующее нажатие той же половины);
  - пауза больше порога (по умолчанию 1 с, настраивается) рвёт цепочку;
  - повтор одной клавиши считается (переход в себя);
  - удерживаемые клавиши (модификаторы, `MO`, `LM`, `TT`, `OSL`, `OSM`) прозрачны
    для маршрутов (клавиши двойного назначения `LT`/mod-tap — нет: при тапе
    они печатают символ):
    `a → MO(1) → (` даёт `a → (`; в тепловой карте они считаются. Переключатель
    «Показывать удерживаемые клавиши в маршрутах»;
  - слой перехода — слой первого нажатия; слой второго хранится тоже.

### Интерфейс

- **Тепловизор**: палитра на выбор — «Акцент» (по умолчанию, от нейтрального
  к акцентному цвету приложения), «Янтарь», «Ледник», «Графит» и ironbow
  («Тепловизор»). Кроме ironbow, холодный край близок к фону страницы, а горячий
  контрастнее всего с ним: темнее в светлой теме, ярче в тёмной. Каждая
  клавиша — источник тепла с плавным
  затуханием, радиус около 0,7 клавиши, без смешивания между половинами. Поверх —
  полупрозрачные контуры и бледные подписи клавиш выбранного слоя. Числа
  (нажатия, %) — в подсказке при наведении. Отдельный цвет для «0 нажатий».
  Шкала логарифмическая (переключатель на линейную).
- **Слои**: переключатель как на вкладке «Раскладка» + «Все слои» (по
  умолчанию; подписи с базового слоя).
- **«Паутинка»**: по клику клавиша выбирается; рисуются стрелки к топ-N
  следующим клавишам (N настраивается, по умолчанию 5), толщина зависит от
  частоты, стрелки акцентного цвета с ореолом под цвет фона, тепло
  приглушается. Повтор той же клавиши — только в таблице. На слое N
  показываются переходы, начавшиеся на слое N. Переключатель
  исходящие/входящие. Таблица по выбранной клавише: «→ K (слой 0) — 34 %».
- **Календарь как на GitHub**: 52 недели, цвет ячейки — нажатия за день на
  выбранном слое (в выбранной палитре). Клик — день, Shift+клик — диапазон; пресеты «эта
  неделя», «прошлая неделя», «всё время». По умолчанию — текущая неделя.
- «Очистить статистику» с подтверждением: за выбранный период или всё.
- Пока клавиатура заблокирована, рядом со статусом сбора — кнопка
  «Разблокировать» (обычная разблокировка Vial).

### Вне первой версии

- Эргономические метрики (одним пальцем подряд, чередование рук, нагрузка на
  пальцы) — нужно указывать, каким пальцем нажимается каждая клавиша.
- Экспорт CSV/JSON.
- Сбор без разблокировки Vial / события нажатий из прошивки Ergohaven.
- Слои, которые включает сама прошивка (auto mouse layer) — не видны
  симулятору.

## Известные ограничения

- Если две клавиши нажаты в пределах одного опроса (16 мс), их порядок не
  определить; `MO` и клавиша в одном опросе попадут на базовый слой.
- `LT`/`OSL`/`TG` симулятор моделирует приближённо (см. план); для раскладки
  автора не используются.
- Опрос по Bluetooth (80 мс) пропускает быстрые нажатия.

## Наблюдения по раскладке автора (K:03 v3/v4)

- Слой 5 (FIVE, 11 клавиш мыши) недостижим: на него не ведёт ни одна клавиша.
- Четыре tap dance определены, но не стоят ни в одном слое.
