# Тепловая карта и маршруты нажатий — план реализации

Спецификация: [key-heatmap-design.md](key-heatmap-design.md).

Сборка: egui 0.34 требует rustc ≥ 1.92 (`cargo +1.92.0 …`). `cargo fmt`
по всему репозиторию трогает чужие неотформатированные файлы — форматировать
только свои (`rustfmt +1.92.0 --edition 2021 <файл>`).

Принцип: логика (подсчёт, слои, половины, хранение) — чистые структуры без
`EntropyApp` и egui, покрытые unit-тестами; UI — тонкий слой поверх. Каждый
этап собирается и проходит `cargo test` сам по себе.

## Этап 0. Проверка фонового опроса в трее (Windows)

Риск: `logic()` может вызываться реже, когда окно скрыто в трей, и частота
опроса проседает.

1. Временный лог: число вызовов `finish_matrix_tester_poll` в секунду при
   включённом Layout Indicator — окно видно / свёрнуто / скрыто в трей.
2. Если частота держится около 60 Гц — идём дальше. Если нет — вынести опрос
   статистики в отдельный поток с собственным HID-дескриптором или через
   очередь `vial_hid_task` (решаем по результату; добавить этап 3a).

Готово, когда: есть цифры для трёх состояний окна.

## Этап 1. Ядро статистики `src/key_stats.rs` — ✅ готово

Чистый модуль без egui.

- `KeyPos { layer: u8, matrix_idx: u16 }`.
- `DayStats { presses: HashMap<KeyPos, u32>, transitions: HashMap<(KeyPos, KeyPos), u32> }`
  (сериализация — списком пар, т.к. JSON-ключи только строки).
- `KeyStatsStore { version, days: BTreeMap<NaiveDate, DayStats> }` с запросами:
  - `presses(range, layer_filter) -> HashMap<u16, u32>` (по позиции);
  - `transitions_from(pos, range, layer_filter)` / `transitions_to(...)`;
  - `daily_totals(layer_filter) -> BTreeMap<NaiveDate, u32>` для календаря;
  - `clear(range)` / `clear_all()`.
- `Halves`: `split_halves(keys) -> Vec<u8>` (номер половины для каждой
  клавиши): сортировка центров по X, самый большой разрыв, если он заметно
  больше среднего шага (порог ≥ 1,5u) — две половины; иначе одна половина.
- `TransitionRecorder`: последнее нажатие на каждой половине
  (`KeyPos`, `Instant`), порог паузы, флаг «удерживаемые прозрачны».
  `on_press(pos, half, is_held_kind, now)` → обновляет счётчики.

Тесты:
- `Л1 → П1 → Л2` даёт `Л1→Л2`, переходов между половинами нет;
- пауза > порога рвёт цепочку;
- повтор даёт переход в себя;
- `a → MO(1) → (` даёт `a→(` при прозрачности и `a→MO, MO→(` без неё;
- `split_halves` на `src/layouts/k03.json` даёт строки 0–4 / 5–9; на
  несплите — одна половина;
- запросы по диапазону и фильтру слоя; `clear(range)`.

## Этап 2. Вынести симулятор слоёв в `LayerTracker` — ✅ готово (без пункта 3)

Сейчас логика слоёв — методы `EntropyApp` и поля `sticky_layout_*`, и
вызывается при отрисовке окна индикатора. Нужно вызывать её на каждом
результате опроса, независимо от индикатора.

1. Новая структура `LayerTracker` (поля `prev_pressed`, `pressed_key_layers`,
   `toggled_layers`, `active_combos`, `tap_dance_states`, `base_layer`) и метод
   `update(&mut self, layout, combos, tap_dances, pressed) -> LayerUpdate`.
   Он возвращает активный слой и список новых нажатий
   `(matrix_idx, source_layer, effective_keycode)`.
2. `sync_sticky_layout_layer_state` превращается в обёртку над `LayerTracker`;
   поведение индикатора не меняется (существующие тесты
   `layout_indicator*` проходят без правок).
3. *(Перенесено в этап 3.)* Трекер обновляется один раз на каждый результат опроса (в
   `finish_matrix_tester_poll`), индикатор только читает его состояние —
   иначе две копии симулятора разойдутся.
4. Классификатор «удерживаемая клавиша» (`key_stats::is_held_keycode`):
   модификаторы `0xE0..=0xE7`, `MO`, `LM`, `TT`, `OSL`, `OSM`. `LT` и mod-tap
   не входят — при тапе они печатают символ.

Тесты: tri-layer K:03 (`MO(1)`+`MO(3)` на слое 1 → слой 3); новое нажатие
получает слой, активный до него; `MO` и клавиша в одном опросе → базовый слой
(фиксируем известное ограничение).

## Этап 3. Подключение сбора — ✅ готово

1. `AppSettings::key_heatmap` (`KeyHeatmapSettings`): `enabled` (false),
   `transition_max_gap_ms` (1000), `top_transitions` (5), `log_scale` (true),
   `show_held_keys_in_routes` (false).
2. Фоновый опрос: условие в `poll_sticky_layout_background` расширить до
   «индикатор включён **или** сбор включён» (переименовать в
   `poll_matrix_background`).
3. В `finish_matrix_tester_poll`: `LayerTracker::update` → для каждого нового
   нажатия, если сбор не на паузе, — `KeyStatsStore` + `TransitionRecorder`.
4. Пауза: открыта страница Matrix Tester или Typing Trainer (вся страница
   тренажёра, включая первое нажатие, которое запускает заезд); клавиатура
   заблокирована; не Vial. Частота перерисовки в трее учитывает включённый
   сбор так же, как Layout Indicator.
   Причину паузы хранить для отображения на странице.
5. Хранение: `<config>/entropy/key_stats/<keyboard_id hex>/<YYYY-MM>.json` —
   по файлу на месяц, чтобы автосохранение переписывало только текущий месяц
   (fallback для id — slug имени раскладки). Загрузка при первом нажатии или
   открытии страницы, запись раз в 60 с при изменениях, при отключении
   клавиатуры и в `on_exit`. Нечитаемый файл переименовывается в `.json.bad`,
   а не перезаписывается.
6. Дата — `chrono::Local::now().date_naive()` в момент нажатия.

Готово, когда: включил сбор, попечатал, свернул в трей, попечатал — файл
содержит нажатия и переходы на правильных слоях.

## Этап 4. Страница и тепловизор — ✅ готово

Сделано сверх плана: пресеты периода («эта неделя», «прошлая неделя», «всё
время») и переключатель лог/линейной шкалы уже на странице; календарь этапа 6
добавит к ним произвольный диапазон. Клавиатурная навигация по настройкам на
этой странице отключена, как в Matrix Tester, чтобы печать не листала вкладки.
Отрисовка тепла: текстура в половинном разрешении, пересборка не чаще 400 мс.

1. `SettingsTab::KeyHeatmap`, пункт в Advanced-меню после Typing Trainer,
   ветка в `settings_shell.rs`, модуль `src/ui/key_heatmap.rs`.
2. Шапка: заголовок, переключатель сбора, статус (идёт / пауза и причина),
   переключатель слоёв (переиспользовать стиль из `layout_layer_switcher.rs`)
   с пунктом «Все слои».
3. Рендер тепла — CPU-текстура:
   - сетка ~8 px на 1u в координатах раскладки; для каждой половины отдельно
     сумма гауссовых пятен (σ ≈ 0,35u, обрезка 0,7u) с весом = нажатия
     (лог/линейная нормализация);
   - пиксели вне маски своей половины не получают тепла соседней;
   - LUT ironbow (256 цветов), «0 нажатий» — отдельный холодный цвет под
     клавишей;
   - `egui::TextureHandle` кэшируется по ключу (диапазон, слой, шкала,
     размер, ревизия данных) — пересчёт только при изменении.
4. Поверх: контуры клавиш (`layout_physical_key_rect`), бледные подписи
   слоя (та же функция подписи, что на вкладке «Раскладка»), подсказка при
   наведении: «N нажатий · X %».
5. i18n en/ru для всех строк.

## Этап 5. «Паутинка» и таблица

1. Клик по клавише — выбор (повторный клик / Esc — снять).
2. Топ-N переходов выбранной клавиши (исходящие или входящие — переключатель);
   на слое N — переходы, начавшиеся на слое N.
3. Стрелки: кривые Безье от центра к центру с небольшим изгибом, толщина
   `1..8 px` пропорционально доле, наконечник; переход в себя — кольцо.
   Цвет контрастный (белый/голубой), тепло приглушается до ~40 %.
4. Таблица справа/снизу: клавиша (подпись + слой), число, доля.
5. Настройка топ-N (3/5/10/все) и «показывать удерживаемые в маршрутах».

## Этап 6. Календарь и очистка

1. Сетка 53×7, недели по колонкам, начало недели — понедельник; цвет —
   `daily_totals(layer)` в ironbow (лог-шкала), пустые дни — нейтральный.
2. Клик — день; Shift+клик — диапазон; пресеты «эта неделя», «прошлая
   неделя», «всё время»; по умолчанию текущая неделя. Выбранный диапазон
   влияет на тепло, паутинку и таблицу.
3. «Очистить статистику»: модалка с выбором «выбранный период» / «всё» и
   подтверждением.
